# AE Arrow 构建路线

更新日期：2026-10-05。测试基线：Windows、After Effects 2026（26.x）；具体小版本在阶段 0 记录。

## 1. 产品目标与技术结论

构建一个类似矢量软件中箭头样式设置的 AE 工具：可选类型丰富、头部与线身独立调整、预设快速切换、选中后继续编辑。箭头规格集中在面板里设置，合成窗口用于查看和摆放结果。

当前实施路线：CEP 面板 + ExtendScript 宿主适配器 + AE 原生形状图层。几何、参数和预设模型独立于 CEP，后续通过新增 UXP 适配器迁移。先验证目标 AE 26.x 中面板加载和脚本通信，再投入完整界面。

面板采用 TypeScript、HTML/CSS 和 SVG 预览；第一版可以使用轻量 DOM 界面，按需要再增加 UI 框架。开发构建工具不随面板运行。ExtendScript 输出单独构建成其支持的旧语法，不能直接把现代 TypeScript/JavaScript 代码交给 AE 执行。

原生图层负责最终显示和渲染；SVG 只用于面板预览。面板关闭后，已生成箭头仍可显示与播放。

### 平台依据

- Adobe 的 [CEP 官方 Cookbook](https://github.com/Adobe-CEP/CEP-Resources/blob/master/CEP_12.x/Documentation/CEP%2012%20HTML%20Extension%20Cookbook.md) 提供停靠面板和宿主通信机制，其兼容表列出 AE 25.0 对应 CEP 12；AE 26.x 的具体构建在本机验证后确认。
- Adobe 的 [平台迁移公告](https://blog.developer.adobe.com/en/publish/2026/09/investing-in-the-future-of-creative-cloud-extensibility-uxp-comes-to-our-flagship-applications) 计划在 2026 年 11 月推出 AE 的 UXP 插件公开测试，2028 年 12 月进入 AE 的 CEP 默认禁用阶段，2029 年 12 月移除 CEP；ExtendScript 不受这项迁移影响。上述日期是官方计划，应在实际发布前复核。
- 因此 CEP 是当前交付入口，独立几何核心是长期资产。UXP 的宿主调用、界面和存储需要适配，不承诺原面板可以直接搬过去。

## 2. 第一版交付范围

第一版专注 2D 箭头的创建、样式调整和可靠回编辑。

| 模块 | 第一版内容 | 后续扩展 |
| --- | --- | --- |
| 头部 | 实心三角、空心三角、开放尖角、燕尾 | 自定义头部、更多装饰端点 |
| 两端 | 起点、终点独立选择无、箭头、圆点、方块 | 端点贴合物体边缘 |
| 线身 | 直线、单段三次贝塞尔曲线；实线、虚线 | 折线、多段曲线、圆角折线 |
| 参数 | 颜色、线宽、头部长宽、燕尾凹陷、曲率、虚线间隔、端点间距 | 渐变、可变线宽、复杂轮廓 |
| 编辑 | 创建、读取选中箭头、更新、复制样式、保存与加载预设 | 多箭头批量编辑 |
| 动画 | 第一版先完成静态模式 | 绘制进度、头部跟随、图层连接 |

提供约 12 个内置预设，复用同一套参数组合。每种类型通过统一接口声明可调参数，面板只显示当前类型适用的选项。

规格使用统一单位：尺寸默认以合成像素表达，缩放行为写清楚；可提供“头部尺寸与线宽联动”开关。普通图层缩放仍按 AE 行为缩放整个箭头。

界面布局：样式缩略图、实时预览、两端设置、线身设置、尺寸和颜色、预设、创建或更新。选中对象后自动读取或点击“读取选中”，通信方式由阶段 0 决定。打开面板或读取对象本身不改变工程。

## 3. 架构与数据约定

数据流：面板参数 → 校验 → 几何计算 → SVG 预览／AE 路径数据 → 宿主适配器 → 原生形状图层。

建议目录：

```text
src/
  model/        参数 schema、默认值、版本迁移
  geometry/     曲线、头部、线身裁切和包围盒
  preview/      SVG 预览，使用同一份几何结果
  panel/        控件、预设浏览、交互状态
  bridge/       请求队列、序号、错误响应
  adapters/     CEP 入口；未来的 UXP 入口
host/
  jsx/          创建、读取、更新和撤销封装
presets/        内置样式 JSON
tests/          几何与通信队列的关键测试
docs/           兼容记录、性能记录、安装说明
```

参数至少包含 schemaVersion、path 类型与控制点、stroke、startMarker、endMarker、头部尺寸、间距、样式关联和 static/animated 模式。

几何函数输入完整参数，输出 vertices、inTangents、outTangents、closed 及描边/填充信息。贝塞尔切线在输出给 AE 时转成相对于顶点的切线；预览和 AE 使用统一几何数据，避免两套生成算法产生不同结果。

每个箭头优先使用一个形状图层，内部至少分为 Body、Start、End 三个受管理分组。路径坐标使用图层局部坐标，更新样式时保留图层 Position、Rotation、Scale、父子关系与其他非管理内容。

把可回编辑参数保存在图层上的带版本工具元数据中，例如 comment 的专用分段；保留原有用户备注。宿主通过当前合成和目标图层身份定位对象，不依赖可变的图层名称或序号。复制图层后重新识别身份，不用复制出的业务 ID 单独定位。

用户手动修改受管理路径后，参数与图形可能不一致。更新前识别此情况，明确显示“路径已手动修改”，由用户选择按工具参数重建或保留手动结果。需要读回任意手工路径属于后续功能。图层变换和非管理效果可以照常修改。

## 4. 几何实现顺序

1. 直线：计算方向向量与法线，建立头部局部坐标；头部长宽独立，线身长度扣除头部占用和端点间距。
2. 四种头部：分别使用填充轮廓或开放描边。定义尖端位置、接合位置和实际占用长度，避免粗线穿出尖端。
3. 双端样式：起点与终点共用头部生成器，通过方向变换放置。
4. 曲线：由端点和控制点形成三次贝塞尔；头部按端点切线定向。使用有上限、可缓存的弧长近似，按真实距离裁切线身，不能直接用曲线参数比例替代距离。
5. 短线与退化情况：端点重合、切线为零、两端头部总长度超过线身、极大线宽、极端曲率。明确采用限制尺寸或显示校验提示，禁止输出 NaN 或错误路径。

复杂实心宽箭头沿曲线的轮廓扩展暂放后续：它涉及偏移曲线、自交和接合，不能把普通描边改为填充就视为完成。

## 5. 跟手与低消耗策略

分开测量三项：面板反馈时间、宿主属性写入时间、AE 合成画面呈现时间。脚本执行结束不代表 AE 已经完成重绘。

### 静态模式

头部和线身由脚本在编辑时生成，样式几何不保留逐帧表达式。只更新变化的属性；拖动颜色时不重算贝塞尔，修改头宽时不重建整层。路径或头部类型切换只更新相应受管理分组，图层结构完整性每次提交后校验。

静态模式仍可使用 AE 常规变换动画。规格参数连续动画在后续动画模式实现；给静态路径直接打关键帧后，面板更新不能静默覆盖既有动画。

### 面板与宿主通信

- 面板预览在本地立即更新，目标是参考机上 p95 响应小于 33 ms；这是验收目标，并非已测结果。
- 宿主请求串行，一次只执行一个写入；后续拖动事件仅保留最新参数。每次携带请求序号，旧回调不能覆盖新状态。
- 用户操作开始时锁定目标；提交前复核合成、图层身份和有效性。切换选择或删除图层时取消待提交的旧操作。
- AE 实时更新从每秒最多 10 次开始试验，根据实测自适应降频；松手后保证提交最终值。
- 交互过程中不重复扫描全部图层，不建立后台高频轮询。首版先验证选择事件；不足时在面板获得焦点或点击读取时同步。
- 静态缩略图缓存；只重绘当前预览。关闭面板后停止面板任务和监听。

### 撤销是首个技术门槛

先实现“本地连续预览、松手一次写入”，确保一次拖动对应一次撤销。对合成窗口实时更新单独做原型：核实目标 AE 上跨调用的撤销行为和中断恢复，不能假定多次 evalScript 调用天然属于一次撤销。

实时模式只有在撤销、目标锁定、最终值提交都通过时启用。若无法在公开接口内可靠实现，首版明确采用松手提交，并保留手动“应用”；合成预览策略在界面上清楚显示。不能为了显得实时而堆积撤销记录。

### 动画模式

只在需要时创建少量表达式和控制参数。绘制动画的箭头头部需要跟随绘制位置和切线，单独添加 Trim Paths 并不能完成此行为。端点与头部几何尽量直接计算，避免各表达式重复执行高密度路径采样。单独测动态模式的消耗。

## 6. 开发阶段与验收

以下是单人开发、已有基本 AE 脚本和前端经验的初步工作量估计，不是固定交付日期；未知兼容问题单列处理。

| 阶段 | 预计工作日 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 0：通信与性能验证 | 1–2 | 最小 CEP 面板、一个直线箭头、时序与撤销记录 | AE 26.x 加载、请求/回调、创建/读取/更新、单次撤销与异常恢复通过；确定预览提交方式 |
| 1：参数与几何核心 | 2–3 | schema、直线和四种头部、SVG 预览、边界测试 | 各头部尺寸可独立修改，退化输入受控；预览与输出几何一致 |
| 2：原生图层编辑闭环 | 2–3 | 创建/读回/更新、元数据、保存重开 | 图层变换保留，复制后可编辑，重开工程仍能读取，旧请求不会改错对象 |
| 3：样式面板与预设 | 2–3 | 缩略图、参数控件、约 12 个预设、用户预设 JSON | 选中回读与反复切换可用；不适用参数隐藏；预设导入有 schema 校验 |
| 4：曲线、虚线与双端 | 2–3 | 单段曲线、端点切线定向、裁切与衔接 | 极短路径和大头部有合理处理，虚线不穿头，曲线样式切换一致 |
| 5：性能与发布 | 2–3 | 性能表、兼容表、签名安装包、说明 | 性能目标实测；关闭面板后图层正常；干净环境安装通过 |
| 6：动画与批量功能 | 另行估算 | 绘制动画、动态图层连接、批量编辑 | 在静态版本稳定后分别验收性能和关键帧保护 |

静态版本初步估计 11–17 个工作日；额外预留 2–4 日处理兼容和边界问题。阶段 0 若失败，先修复桥接或以 ScriptUI 调试宿主功能，再决定面板路线，不继续堆完整 UI。长期 UXP 迁移单独立项，待目标版本 API 和分发流程可用后进行。

## 7. 性能测试与发布门槛

记录 CPU、GPU、内存、AE 小版本、CEP 运行时、合成分辨率、预览分辨率和缓存状态。默认用 1920×1080、30 fps 的 2D 合成，另测 4K 场景。分别测试 1、20、100 个静态箭头；一次更新一个和批量更新必须分开统计。

| 指标 | 暂定目标 | 测量方式 |
| --- | --- | --- |
| 面板连续反馈 | p95 < 33 ms | 控件事件到 SVG 更新，用浏览器性能时间戳记录 |
| 单箭头最终提交 | p95 < 150 ms，不含 AE 重绘 | 提交到宿主完成回调，暖启动至少 100 次 |
| 输入停止后的最终状态 | 最新值最终落地，无旧值回跳 | 连续拖动、切换目标、快速切换类型 |
| 撤销 | 一次已提交操作可可靠恢复 | 拖动、样式切换、创建后撤销/重做 |
| 静态渲染成本 | 相同路径与属性下接近手工原生图层；初步容差 +10% | 相同工程与缓存策略，重复比较渲染耗时的中位数 |
| 面板闲置 | 无持续宿主调用，无单调内存增长 | 打开/关闭/重新打开及持续使用 30 分钟 |

这些数值是参考机上的调优目标。若单箭头提交不达标，先拆分几何耗时、通信耗时与属性写入耗时，找到瓶颈，再决定是否调整实时频率或目标；不能以“原生图层”直接宣称没有开销。

有意义的自动验证：头部尖端和宽度、两端方向、曲线裁切与切线、短路径保护；请求队列只保留最新值、失效目标取消写入、旧 schema 迁移。宿主生命周期、撤销、工程保存和显示一致性在 AE 实机验证。

发布前还需验证锁定图层、无活动合成、重复图层名、用户修改分组、路径已有关键帧、撤销后元数据一致性、中文与英文 AE。首个支持环境为 Windows + 实测的 AE 26.x 小版本；其他平台在验证后扩展声明。

## 8. 第一个可执行任务

先做阶段 0：一个能停靠的面板，包含线宽、头长、头宽、颜色四个参数和 SVG 预览，以及“创建、读取、更新”三个操作。只生成一个实心三角直线箭头。

这一小版本必须证明：连续调整顺畅、最终值正确、图层可回编辑、一次操作可撤销、保存后可恢复。通过后，再扩充箭头类型与样式库。

## 9. 本轮实施记录（2026-10-05）

用户要求先尝试脚本构建、稍后测试，因此先交付独立 ScriptUI `.jsx` 构建稿，替代阶段 0 的 CEP 界面入口；原生图层与几何核心保持分离，后续可继续接入 CEP/UXP。

当前源码包含：独立起终点类型与尺寸、四种箭头头部和三种装饰端点、直线/单段曲线、虚线、示意预览、12 个预设、创建/读取/更新、参数元数据、手动改动与动画保护。面板预览连续更新，合成图层按手动操作或滑条松手提交。

构建入口为 `dist/AE Arrow.jsx`，使用说明见 `README.md`。随后按用户要求在 AE 26.0x67 执行实机测试，修复虚线隐藏属性检测，并减少更新过程中的属性遍历与重复写入。测试记录见 `TEST_REPORT.md`；完整性能验收条件仍待覆盖，不能把脚本执行耗时等同于面板交互帧率。
